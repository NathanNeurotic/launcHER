# POPStarter r13 → launcHER original-behavior parity matrix

> Evidence checkpoint: 2026-10-20. Work on [draft PR #23](https://github.com/NathanNeurotic/launcHER/pull/23), branch `codex/popstarter-replacement`. **Not** a declaration of drop-in parity. This is a focused executable-behavior oracle and acceptance queue to use alongside [the broader implementation diary](POPSTARTER_REPLACEMENT.md), [the Sony I/O contract](POPS_IO_CONTRACT.md), and [the hardware handoff](CLOUD_CONTINUATION.md). Never merge or release as 1:1 while the gates below remain open.

## Evidence labels and provenance

- **O — Original measured**: pinned original POPStarter or Sony instructions were unpacked/inspected, or executed in bounded controlled probes. Static calls do not prove every branch executes on a console.
- **S — Replacement synthetic**: launcHER production code passes host tests or an isolated PS2 probe, but is not proven in a complete POPS game session.
- **H — Replacement hardware**: an actual console test reached the specifically recorded boundary. A preflight probe is not a gameplay test.
- **U — Unknown**: a claim, reconstructed helper, historical description or proposed patch is not established by equivalent original-binary behavior. Do not silently equate support with parity.

Original selected archive: POPSLoader `PROFILES/MAIN/POPSTARTER.ELF`, SHA-256 `734c813e8e8ec2c6729ec5e15dd46ab696e90deeade8d0b2ca3ad03782781aa1`. Bounded decompression produced 1,350,828 bytes, SHA-256 `185177c28aaef30ad1e00697ad7b6de22b55bd855253ab4ede8b1ab2dfb08aee`. This establishes one selected archived profile, **not** every file labeled POPStarter r13. Original game/core files must remain external. See [POPS_IO_CONTRACT.md](POPS_IO_CONTRACT.md) and REPOP `docs/POPSTARTER_PFS_WRAP_EVIDENCE.md`.

REPOP `parity/baseline.json` currently records **477 eligible EE functions / 139,144 bytes, zero annotated parity claims** for POPStarter. The raw `parity/popstarter/ground_truth.json` contains more entries, including embedded IOP code and unusable decompilation boundaries. `tools/parity_report.py` explicitly filters embedded-IOP address range `0x0091f680..0x0099ddcc`, suspect oversized functions and corrupt exports. Therefore the raw and eligible counts are different measures, not a reason to trust the speculative `popstarter/src` scaffold. Track IOP separately (`parity/popstarter_iop`).

## Controlled progression; minimize failed console tests

1. **Dependency gate**: capture failing POSIX stage and independent fileXio result on the exact same external file. Confirm digest only after complete read and close. A trace build must **never** turn its comparison buffer into a successful Sony handoff.
2. **Bootstrap gate**: require dependency/profile hash, post-reset module/legacy IOMAN binding and unambiguous evidence of entry to the **actual** Sony runtime (the preflight marker alone does not count).
3. **Read-only gameplay gate**: known-good VCD title/region on APA or USB, TOC/sector transcript and controller/audio/video capture.
4. **Writable-save gate**: **new dedicated test VMC only**, write/read/reset/power cycle. Existing user VMCs must never be truncated, reformatted or replaced to satisfy testing.
5. **Feature gate**: controlled games for mode and fix corpus, LibCrypt, CDDA, disc change, cheats, IGR, video; compare original to launcHER on identical firmware, game content and settings.
6. **Storage-extension gate**: only then extend console testing to SMB, multi-USB, MX4SIO, MMCE, i.Link, UDPFS/UDPBD; test lost packets, reopen, error propagation, device reset and persistence independently.
7. **Release gate**: no automatic promotion of unverified status or merge of PR #23. Build/test success is not synonymous with complete parity. Keep original files, ROMs, unpacked binaries and memory-card images outside the repository.

Reproducibility: `python tools/test_pops_external.py`, `python tools/test_pops_read_trace.py`, `python tools/test_pops_fix_files.py`, `python tools/test_pops_modes.py`, `python tools/test_popfs.py`; use PR CI for complete PS2SDK build and opt-in `-DLAUNCHER_BOOT_TRACE=ON -DDEBUG=ON` artifact. Correlate every hardware claim with a pinned branch SHA, output ELF SHA-256, device, original version, log/probe hash and the exact success boundary. Historical run records under `docs/evidence/` are not substitutes for the next boot result.


## Reverse-engineering function anchors (selected pinned profiles)

**Decompiler provenance warning:** REPOP's archived `popstarter/ghidra/output/decompiled.c` identifies its processor as `MIPS:LE:64:64-32addr`, whereas the current eligible EE ground-truth export identifies `r5900:LE:32:default`. The archived C is a useful lead for finding callsites, but it is **not** itself an R5900-validated function-parity claim. Corroborate each high-priority path against a current CLEAN R5900 export, instruction bytes and bounded original execution before changing production runtime behavior.


These are exact **entry/callsite addresses in the identified original images**, not addresses to write into arbitrary POPS versions. Validate profile SHA-256 and original bytes before translating any fix. A known callsite does not establish every conditional path.
