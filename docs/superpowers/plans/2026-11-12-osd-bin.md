# `OSD.BIN` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add drop-in POPStarter r13 `OSD.BIN` validation, staging and launch paths to launcHER, with original-under-Unicorn differential evidence and no Ember changes.

**Architecture:** A pure header planner and bounded core/state stage live in `pops_modes_patches.c`. A thin reader in `handler_pops.c` preserves original file operations, while BIOS-style look-ahead supplies loader state to the existing grouped command pass. The original MAIN is the behavioral oracle under Unicorn; REPOP is a reference, not the proof.

**Tech Stack:** C99, Python 3 `unittest`/`ctypes`, Unicorn MIPS64, PS2SDK CMake/Docker, existing host wrappers and CI.

**Spec:** `docs/POPSTARTER_OSD.md` (owner-approved on 2026-11-12), with clean REPOP `bc258e48` `popstarter_load_user_osd` at `popstarter/src/main.c:734-1035`.

## Global Constraints

- Match r13 exactly first, bugs included. Do not improve the v2 delay-slot instruction, read checks, or mixed-scope residue.
- POPStarter launches only; Ember behavior and its launch path must not change.
- Do not reorder production files/commands. Quirk 80 and every newly measured difference must be indexed, starting at 81.
- Use synthetic files only. Never commit, print or log proprietary reference contents, disc images, BIOS images or keys.
- Keep evidence levels distinct: code review, host tests, Unicorn, PS2SDK build, PCSX2 and real console. No console or game-boot claim from this plan.
- Preserve independent review before one `--no-ff` merge into `codex/popstarter-replacement`; PR #23 stays draft.

## Review Focus

- Rejection precedence and atomicity: invalid combinations must return the first r13 reason without core/state writes (Tasks 1, 2).
- Unaligned, short and failed reads: preserve request size and zero-fill behavior without a new fatal path or overflow (Tasks 1, 3).
- Built-in no-fix and OSD-off state: header modes must see the built-in flag and sequential root/game state, not later text state (Tasks 2, 4).
- Mixed v2/v1 scopes and intentional guard updates: residue must match while later BIOS/PATCH guards remain effective (Tasks 2, 4).
- Look-ahead/file-change behavior: predicted command state must match actual loads or stop with `-EIO`, without changing Ember or accepting arbitrary guard bytes (Task 4).

```c
typedef enum {
  POPS_OSD_REJECT_NONE = 0,
  POPS_OSD_REJECT_NOT_FILE = 2,
  POPS_OSD_REJECT_VERSION = 3,
  POPS_OSD_REJECT_HEADER = 4,
  POPS_OSD_REJECT_LOAD = 5,
  POPS_OSD_REJECT_ENTRY = 6,
  POPS_OSD_REJECT_SIZE = 7,
  POPS_OSD_REJECT_TOO_BIG = 8,
  POPS_OSD_REJECT_BUILD = 9,
  POPS_OSD_REJECT_LABEL = 10
} PopsOsdReject;

typedef struct {
  uint8_t header[64];
  int64_t file_size;
  uint32_t body_size, body_request, body_address, body_capacity;
} PopsOsdPlan;

int pops_osd_plan(const void *header, size_t header_read,
                  int64_t file_size, PopsOsdPlan *plan);
int pops_osd_stage(void *core, size_t core_size, const PopsOsdPlan *plan,
                   const void *body, size_t body_read,
                   int per_game, PopsUserRomState *state);
int pops_user_osd_skipped(int per_game, const PopsUserRomState *state);
```
`pops_osd_plan` returns 0 for a usable plan, a `PopsOsdReject` value, or negative errno. `pops_osd_stage` returns 1 loaded, 0 gated, or negative errno; a NULL core is a state-only look-ahead. Rejections and errors are atomic. Extend `PopsUserRomState` with byte fields for integrity, built-in no-fix, abort and game-directory-missing state.

Prevalidate all destination/compat ranges before writing. `body_request` is body size plus 16 only under the measured unaligned condition. Stage clears the applicable cap, copies at most the delivered bytes, zeroes from body size, applies v1/v2 code, enables OSD if needed, applies valid modes in header order with no-fix gating, sets scope flags and `0x20079a`. State-only calls share the same sequential state logic without touching a core.
