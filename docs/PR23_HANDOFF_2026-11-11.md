### 3.2 Handoff defect (`pr23/handoff`, 1 unfinished commit, based on `cfebe01`)

The defect, read from the SCPH-39001 kernel and seen in PCSX2, not checked
on a console: `ExecPS2` terminates every other thread, and for a thread that
is not dormant the kernel rewrites four words of its initial frame (gp, sp,
fp, ra at stack end - 0xe0 / 0xd0 / 0xc0 / 0xb0). launcHER has such a thread
(the SDK's helper, 0x400-byte stack in launcHER's own data). In current
builds that stack lies above 0x200000, so the four words land in POPS code
the trampoline has just copied there (trace build: 0x206360..0x206390;
release build: 0x202ca0..0x202cd0). October builds had the stack below
0x200000, which may be why the hardware run then reached gameplay. A second
weakness: the trampoline zeroes 0x100000..0x200000 while launcHER's timer
(INTC 11) and SIF (DMAC 5) handlers are still registered.

Reports: [handoff-defect-static.md](handoff/2026-11-11/handoff-defect-static.md),
[handoff-defect-emulator.md](handoff/2026-11-11/handoff-defect-emulator.md).

The unfinished fix terminates and deletes launcHER's other threads just
before the trampoline, puts the freed thread slots back in front of the
kernel's free queue so POPS's threads get the ids they get after POPStarter,
and turns interrupts off at the top of the trampoline. It adds
`common/src/pops_handoff.c`, `launcher/src/pops_handoff_ee.c`,
`tools/test_pops_handoff.py` and `tools/check_pops_handoff_layout.py`.

Its author was stopped before reporting. The author's run log
([handoff-fix-scratch/runs.log](handoff/2026-11-11/handoff-fix-scratch/runs.log))
lists scratch builds of a second variant that passed the PCSX2 probes 3 of 3
with the recompiler up to the handoff and 3 of 3 with the interpreter up to
POPS's video setup. Those runs were not repeated and it is not recorded
which state of the tree they used. Treat the branch as a lead: read it,
rebase it onto the PR branch, run its tests, rebuild, repeat the emulator
runs, have it reviewed.

### 5.3 CHEATS.TXT pass: review 1, not fixed

Full text: [cfg-text-review-1.md](handoff/2026-11-11/cfg-text-review-1.md).

1. Major: `$FORCEPAL` after a `$480P` (same file or the earlier file) has an
   effect in launcHER and none in the original. The original's handler
   (0x8987f0) stores only while gp+0x3864 is 0, and `$480P` sets it. Not a
   regression: the old parser did the same.
2. Major: two one-line changes to the cheat-code column test in
   `common/src/pops_config.c` pass every committed test. The code is right;
   the tests do not pin it.
3. Minor: launcHER's own token splitter cuts a token at 63 bytes, so 63
   non-blank bytes followed by a digit add a compatibility mode.
4. Minor: that splitter uses `isspace`/`isdigit`, which depend on the
   locale for bytes above 0x7f on the host.
5. Minor: files shorter than about 8 bytes: the original reads past its
   buffer; the document does not say so.
6. Minor: a count in a commit message and a printed string are off.
7. Minor: the test recipe must also set `TMPDIR` (see section 6).

Still open from the author's report: launcHER-only tokens, bare digits and
`MODE n` are still read from CHEATS.TXT, where the original ignores them.
Under the exact-parity rule they should stop being read from that file.

## 6. How to check a tree

Host tests, from the repository root, one file after another (two runs at
once collide on `build/pops-host`):

```sh
export TMP=<empty dir> TEMP=<same> TMPDIR=<same>
for t in tools/test_*.py; do python "$t" || echo "FAILED $t"; done
```

Run them once with no reference inputs (this is what CI does; tests that
need the originals skip) and once with `POPS_TEST_ELF` (Sony `POPS.ELF`) and
`POPSTARTER_TEST_ELF` (POPStarter r13 `MAIN` profile ELF) set. The originals
are never committed.

Target build:

```sh
docker run --rm -v <repo>:/workspace -w /workspace ghcr.io/ps2homebrew/ps2homebrew:main \
  sh -c "apk add cmake && git config --global --add safe.directory /workspace && cmake -B build-pr23 && cmake --build build-pr23 --target launcHER"
```

Emulator: the scripts used for the PCSX2 runs are in
[handoff/2026-11-11/emulator-harness/](handoff/2026-11-11/emulator-harness/REPORT.md).
They expect a private copy of the emulator, a BIOS and disk images that are
not in the repository; `REPORT.md` there says how the runs were set up and
which results are only leads.
